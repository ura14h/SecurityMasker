## Source artifact

clean worktreeのtag commitから`./scripts/package-source`でarchiveとchecksumを生成した。

1. 別のclean local cloneから同じtag treeを生成し、archiveのbyte-for-byte一致を確認した。
2. tagを明示した`git archive`からも同一SHA-256になることを確認した。
3. archiveにmodel weight、`.venv`、`dist`、`__pycache__`、state、key、DB、`.pyc`がないことを
   検査した。
4. 新しい一時directoryへ展開し、標準`setup`で固定dependencyと固定NER modelのdigest検証を
   完了した。
5. clean展開先で`--version`、launcher隣接`init`、`config-check`、標準NERを使う`preview`、
   `client-config`が成功した。

## Release中に修正したgate

1. Anthropic必須gateがmodel未指定でClaude Codeの既定modelへ依存していた。既存evidenceと同じ
   `haiku`を標準値に固定し、修正後の正式gateを完走した。
2. Linux release imageがWindows契約testの参照するlock fileをbuild contextへ含めていなかった。
   Dockerfileとdockerignoreを修正し、全gateを最初から完走した。
3. POSIX版`package-source`が文書化済みの`SECURITYMASKER_PYTHON`を受け取っていなかった。
   Windows版と契約を揃え、別clean cloneから同一archiveを生成した。

いずれも合格扱いにせず修正し、影響するgateを再実行した。製品のmasking、protocol、store、DACL
実装にrelease中の変更はない。

## 結論

source版1.0.0について、対応platformの必須gate、実provider E2E、Windows native保護境界、
source artifactの再現性とclean展開を確認した。source release scope内の未実施項目はない。
binary版の署名、再配布条件、clean-machine gateは未完のため、binary artifactは公開しない。
